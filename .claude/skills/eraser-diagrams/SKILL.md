# Правка диаграмм eraser-diagrams

Применяй при любой правке `rk*/diagrams/*.json`. Один файл = одна схема,
схемы не сливать. PNG рендерится рядом с JSON, рядом же лежит
`<name>.png.sha256` (хеш исходного JSON). PNG и `.sha256` коммитятся
вместе с JSON.

## Формат, который принимает CLI 0.1.0

- Документ: `{ "entities": [...], "connections": [...] }`.
- Теги с учётом регистра: `Group`, `Icon`, `Activity`, `Textbox`, `Legend`, `Relationship`. У `Legend` обязательна `width`.
  `group` не распознаётся.
- У каждой сущности обязательны `tag`, `id`, `x`, `y`. У `Textbox` ещё `text`.
- **Координаты абсолютные, даже у детей с `containerId`.** `containerId`
  задаёт только логическую вложенность. Позицию узла внутри группы считай
  от левого верхнего угла группы сам: первый узел на `x+20, y+40`.
- Текст: `Icon`/`Activity` → `texts: [{ "text": "..." }]`;
  `Group` → `title: { "text": "...", "icon": "..." }`; `Textbox` → `text`.
- Стрелка: `{ "tag": "Relationship", "from": "<id>", "to": "<id>", "label": "..." }`.
  `from`/`to` могут указывать на `Group`.
- Автораскладки узлов нет, раскладываются только линии.

## Сетка и размеры

- Сетка 20 px. `Icon` занимает ячейку ~100×100 (иконка + подпись снизу),
  шаг 140 по горизонтали, 120 по вертикали.
- `Activity` задавай явно `"width": 120, "height": 60`, шаг 160.
- У `Group` 40 сверху под заголовок, 20 по остальным сторонам. Ширина под
  N иконок в ряд: `140·N`, под N `Activity`: `160·N`.

## Раскладка

Роутер стрелок глобальный: сдвиг одного узла или даже изменение размера
группы перестраивает маршруты по всей схеме. Меняй один параметр за раз и
смотри PNG после каждого рендера.

- Длинные подписи иконок переносятся по ~100 px в 3–5 строк. Держи узлы в
  40 от рамки группы, а не в 20, иначе подпись касается границы.
- Две стрелки, входящие в узел с одной стороны, кладут подпись одной на
  линию другой. Ставь цель так, чтобы стрелка шла прямо: например, узел
  строго под источником — вертикальная стрелка без изломов.
- Стрелка к группе (`to` — id группы) входит у её левого верхнего угла.
  Держи этот угол пустым, иначе её читают как стрелку к узлу в углу.
- Несколько стрелок из одной иконки выходят с шагом ~16 px, их подписи идут
  почти вплотную. Это задаёт рендерер: сдвиг самой иконки выше или ниже
  делал только хуже. Прими как есть или пробуй менять положение целей,
  проверяя PNG после каждого шага.
- Подпись стрелки не переносится, если горизонтальный участок стрелки
  длиннее текста. Для подписи в ~40 символов нужен зазор между узлами ~300+.

## Иконки

- Имя в `icon` берётся из `icons.txt`: `grep -xi '<имя>' icons.txt` или
  `grep -i '<слово>' icons.txt`. Неизвестное имя роняет сборку.
- Нет в каталоге — бери общую (`server`, `database`, `monitor`, `bell`,
  `package`, `rocket`, `cloud`, `globe`) и пиши название в подписи.
- Обновить снимок каталога: `bun run icons`.

## Поля тега

`bunx eraser-diagrams schema <Tag>` печатает JSON Schema, например
`bunx eraser-diagrams schema Activity`.

## Цикл правки

1. Измени JSON. Новые группы и стрелки сразу крась по разделу «Цвета».
2. `bun run validate` — схема, без браузера. Имена иконок он не проверяет:
   незагруженные иконки validate пропускает.
3. `bun run check` — цветовая конвенция и легенда, без браузера. Сообщение
   называет id элемента и нужные значения.
4. `bun run warm` — докачивает иконки всех схем в `.eraser/icons` с
   повторами; неизвестное имя роняет с текстом `unknown icon`. Рендер
   после прогрева в сеть не ходит.
5. `bun run render` — пишет `<name>.png` и `<name>.png.sha256` рядом с
   JSON. Рендер идёт в Docker-образе из `Dockerfile`, как в CI: Docker
   Desktop должен быть запущен, иначе команда остановится с подсказкой. Без
   Docker: `DIAGRAMS_NATIVE=1 bun run render` (нужен Chrome на хосте или
   `CHROMIUM_PATH`).
6. Открой `<name>.png` через Read и проверь глазами: узлы не накладываются,
   все узлы внутри своих групп, заголовки групп не обрезаны, подписи
   читаемы, легенда ничего не перекрывает.
7. Поправь координаты (кратно 20), повтори с шага 2.
8. `bun run fresh` — хеши рядом с PNG совпадают с JSON; падает с именем
   устаревшей схемы.
9. Перед коммитом полная цепочка из `CLAUDE.md`.

## Цвета

Источник истины: `scripts/colors.ts`, проверка: `bun run check`.

Верхние группы красятся по зоне:

| Зона | `color` верхней группы |
| --- | --- |
| Браузер пользователя | `blue` |
| Наши серверы: API, БД, Redis | `green` |
| Злоумышленник: чужой сайт, внедрённый скрипт | `red` |

- Вложенная группа: `color` родителя и `"styleMode": "plain"`. У верхней
  группы `styleMode` не задавай.
- У иконок, шагов `Activity` и остальных элементов `color` не бывает.
- Группа не подходит ни в одну зону: не выдумывай цвет, это правка спеки.

Тип стрелки определяется по зоне источника (`from`, через `containerId` до
группы). Правила сверху вниз:

| Источник | `color` | `lineStyle` | Легенда |
| --- | --- | --- | --- |
| узел в группе `attacker` | `red` | `dotted` | Атака |
| узел в группе `cookie-jar` | `orange` | `solid` | Браузер прикладывает сам |
| узел в группе `js-context` | `black` | `dashed` | Делает код фронта |
| остальное | не задавать | не задавать | Прочие связи |

Фиксированные id групп, по ним работает проверка:

- `attacker` — верхняя группа красной зоны «Злоумышленник»;
- `cookie-jar` — группа «Хранилище cookie» внутри верхней синей группы;
- `js-context` — группа «JS-контекст страницы» внутри верхней синей группы.

С другим id стрелки из этих групп станут «Прочими связями».

Легенда: ровно один элемент `"tag": "Legend"` с `"id": "legend"`, явными
`x`, `y` и `"width": 340`, без `color`, `containerId`, `styleMode`. Ставь её
справа от содержимого на `y: 0`. Пункты: только зоны верхних групп и типы
стрелок, которые есть на схеме. Если правка поменяла состав зон или типов
стрелок, `bun run check` напечатает нужный массив `entries`; скопируй его в
легенду.

## Соглашения

- `id` в kebab-case, уникальны в файле, осмысленны: `api-server`, не `n17`.
- Подписи коротко, без URL внутри `texts`; URL только в `label` стрелки.
- Домены в примерах: `example.ru`, `api.example.ru`, `avatars.example.ru`,
  `evil.example` (чужой сайт). Реальные IP, токены, внутренние адреса
  запрещены: репозиторий публичный.
- Никаких `x-`-полей и стилей сверх необходимости. Цвета только по разделу «Цвета».
- Связи не выдумывать: только те, что описаны в тексте документа или спеке.

## Известные ловушки

- Плейсхолдеры в угловых скобках (`<id>`) в значениях `label`/`text` диаграммы
  (не в этой инструкции, где `<Tag>` и `<имя>` — просто обозначения) вырезает
  HTML-санитайзер CLI, `validate` падает с `W_CONTENT_SANITIZED`. Пиши `{id}`.
- Ширина переноса подписи на стрелке зависит от горизонтального хода
  стрелки от исходного узла. Почти вертикальная стрелка ломает URL
  посреди слова; дай стрелке горизонтальный участок (сдвинь узел по x).
- Роутер стрелок обходит иконки, но не заголовки групп: линия может
  пройти через полосу заголовка. Если текст читаем, это косметика.
- Подписи с `https://` CLI рисует синим цветом ссылки; цвет подписи не трогай.
- Прямой апостроф `'` в тексте (`Let's Encrypt`) даёт ложный
  `W_CONTENT_SANITIZED` в `bun run validate`: marked экранирует его в `&#39;`,
  санитайзер раскодирует обратно, CLI видит расхождение. Пиши типографский `’`.
- `text` у `Textbox` — Markdown (GFM): текст между двумя `~` зачёркивается.
  Пути вида `~/.config/…` бери в обратные кавычки.
