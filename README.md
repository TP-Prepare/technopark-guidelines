# Гайдлайны Технопарка: рубежные контроли командного проекта

Ожидания преподавателей Технопарка (VK Education, курс по веб-разработке, 2-й семестр) к
рубежным контролям командного проекта. Команда из четырёх студентов — два фронтенда и два
бэкенда — делает фуллстек-аналог сервиса. На каждом рубежном контроле (РК) проверяют, что
работает и что команда понимает, как это устроено.

## Для кого

- **Студенты** — что обязательно сделать к РК, объяснение, как это устроено, самопроверка и
  подготовка к вопросам на защите.
- **Менторы и преподаватели** — чек-лист приёмки и вопросы с критериями ответа.

Обе аудитории видят все файлы. Критерии ответов спрятаны под раскрывающимся блоком, чтобы
вопросы можно было прочитать без подсказки.

## Рубежные контроли

| РК | Тема | С чего начать |
|---|---|---|
| РК1 | Аутентификация, сессия и доступ к данным | [rk1/README.md](rk1/README.md) |

Пока есть только РК1; материалы следующих РК появятся рядом, в своих папках.

## Как читать

Начните с `README.md` папки своего РК. В нём требования, обязательный минимум (невыполнение
любого пункта — РК не сдан), варианты реализации и маршрут чтения: что читать студенту по
порядку и что нужно ментору. Остальные файлы ссылаются друг на друга, поэтому читать подряд всё
не обязательно.

## Как предложить правку

Нашли ошибку, устаревший пример или непонятное место — напишите. Студенты тоже могут: если
вопрос возник у вас, он возникнет и у следующего потока.

- **Issue** — если хотите сообщить о проблеме или задать вопрос. Укажите файл и раздел.
- **Pull request** — если знаете, как исправить. PR идёт в `main`, в описании — разделы «Что»,
  «Решения», «Проверка». `main` защищён: сливается только PR с зелёным CI.

Правила текста:

- язык — русский, термины — в оригинале (`SameSite`, preflight, CSRF);
- примеры обезличенные: `example.ru`, `api.example.ru`, `avatars.example.ru`, `evil.example`;
  без названий проектов и команд, реальных адресов, IP и токенов;
- утверждение о поведении браузера или стандарта сверяется с источником (MDN, OWASP, RFC 6265bis,
  спецификация Fetch), каждый файл заканчивается разделом `## Источники`;
- заголовки только через `#` (`#`, `##`, …): проверка ссылок не понимает подчёркнутые заголовки.

## Для авторов правок: схемы и проверки

Нужны [Bun](https://bun.sh/) 1.3 или новее и, для рендера схем, Docker.

```bash
bun install
```

Схемы бывают двух видов:

- **Mermaid** — `sequenceDiagram` прямо в Markdown. Участники с короткими ASCII-алиасами
  (`participant B as Браузер`), без `;` и `#` в сообщениях, одна диаграмма — одно событие.
- **Eraser** — JSON в `rk*/diagrams/`, рядом с ним PNG и `.png.sha256`. Правятся только по
  скиллу [`.claude/skills/eraser-diagrams/SKILL.md`](https://github.com/TP-Prepare/technopark-guidelines/blob/main/.claude/skills/eraser-diagrams/SKILL.md):
  формат, цвета, раскладка и цикл `bun run validate` → `bun run check` → `bun run warm` →
  `bun run render` → осмотр PNG → `bun run fresh`. PNG и `.png.sha256` коммитятся вместе с JSON:
  CI схемы не рендерит, а только проверяет, что PNG не устарел.

`bun run render` и `bun run mermaid` идут в Docker-образе из `Dockerfile`, как в CI. Без Docker —
`DIAGRAMS_NATIVE=1` и путь к Chrome в `CHROMIUM_PATH` перед командой.

Перед PR:

```bash
bun run typecheck && bun run test && bun run validate && bun run check \
  && bun run fresh && bun run links && bun run mermaid
```

`links` проверяет относительные ссылки и якоря между `.md`, `mermaid` — что каждая диаграмма
собирается. Подробнее о правилах репозитория — в [CLAUDE.md](https://github.com/TP-Prepare/technopark-guidelines/blob/main/CLAUDE.md).
