# Сайт гайдлайнов на VitePress — дизайн

Дата: 2026-10-06. Статус: на согласовании.

## 1. Цель

Студентам и менторам удобнее читать гайдлайны на сайте, чем в виде `.md` на GitHub: меню по
страницам РК, поиск по всем РК, оглавление страницы, нормальная вёрстка на телефоне, тёмная
тема. Сайт собирается из тех же Markdown-файлов и публикуется на GitHub Pages при каждом
мерже в `main`.

**Главное представление — сайт.** Файлы на GitHub остаются читаемыми, но тексты пишутся под
VitePress: во втором PR в них появятся контейнеры `::: tip` / `::: warning` / `::: danger` и
вкладки, которые GitHub покажет как обычный текст. Разосланные ссылки вида
`github.com/TP-Prepare/technopark-guidelines/blob/main/rk1/csrf.md` продолжают открываться:
файлы не переезжают.

Работа делится на два PR:

1. **Инфраструктура (эта спека).** Сайт собирается из текущих `.md` почти без правок текстов:
   ссылки и якоря, Mermaid и PNG, `<details>`, поиск, меню, русский интерфейс, деплой, проверки
   в CI, архитектура под несколько РК.
2. **Тексты (отдельная спека или bounded-дизайн позже).** Перевод текстов на контейнеры и
   вкладки, подключение `vitepress-plugin-tabs`.

## 2. Решения

| Решение | Почему |
|---|---|
| VitePress **1.6.4** (стабильная), точная версия | 2.0 больше 1,5 лет в альфе, ломает совместимость между альфами. Переход на 2.0 затрагивает конфиг и тему, а не тексты (changelog 2.0.0-alpha.1…20): цена перехода не растёт с числом страниц |
| Сайт собирается из корня репозитория, конфиг в `.vitepress/` | Файлы не переезжают, ссылки на GitHub не ломаются; `docs/` уже занята спеками |
| Тема VitePress по умолчанию, без своего дизайна | Минимум своего кода — дешёвый переход на 2.0 |
| Поиск встроенный (`local`), без Algolia DocSearch | Для десятков страниц хватает; Algolia — заявка, ключи и внешний краулер |
| Mermaid — `vitepress-plugin-mermaid` 2.0.17 | По решению владельца: посмотреть готовый плагин. Риск: плагин не обновлялся с 2024-09 и заявлен только для VitePress 1 (`peerDependencies: ^1.0.0`); при переходе на VitePress 2.0 может потребоваться замена |
| Якоря — функция GitHub (`githubSlug`), общая с `scripts/check-links.ts` | Встроенная функция VitePress даёт другие якоря: `й` → `и` (`#настоичиво-рекомендуется`), `__Host-` теряет подчёркивания. Проверено на `@mdit-vue/shared` |
| Адрес `https://tp-prepare.github.io/technopark-guidelines/` | Без своего домена; домен подключается позже без изменений кода, кроме `base` |
| Нет `llms.txt`, комментариев (giscus), ссылки «Изменить на GitHub», даты правки, журнала изменений | Решено на обсуждении: не решают подтверждённой проблемы. Дата правки — одна строка конфига, если понадобится |
| Нет версий сайта по потокам | Прошлую редакцию находит история git |

## 3. Структура под несколько РК

### 3.1. Папки

Один РК — одна папка `rkN/` (`rk1/`, `rk2/`, …): `README.md` (обзор РК), страницы РК, `diagrams/`
(eraser JSON + PNG + `.png.sha256`). Скрипты (`check-links`, `eraser`, кэш иконок в CI) уже
работают по маске `rk*/` — менять их под новые РК не нужно.

### 3.2. Реестр РК

Файл `.vitepress/rk.ts` — единственное место, где РК публикуется на сайте:

```ts
export interface Rk {
  dir: string;      // 'rk1' — папка в корне репозитория
  title: string;    // 'РК1. Аутентификация, сессия и доступ к данным'
  nav: string;      // 'РК1' — подпись в верхнем меню
  pages: string[];  // имена файлов без .md в порядке меню; первая — 'README'
}

export const rks: Rk[] = [
  {
    dir: 'rk1',
    title: 'РК1. Аутентификация, сессия и доступ к данным',
    nav: 'РК1',
    pages: ['README', 'basics', 'cors', 'variant-a', 'variant-b', 'variant-c',
            'csrf', 'access-control', 'pitfalls', 'checklist', 'questions'],
  },
];
```

Порядок страниц РК1 — маршрут чтения из `rk1/README.md`. Если маршрут в README расходится с
этим порядком, при реализации порядок берётся из README и в реестре правится.

Из реестра конфиг строит:

- **верхнее меню** — пункт на каждый РК (`nav`), ведёт на обзор `/rkN/`;
- **боковое меню** — отдельное на каждый РК, привязано к префиксу `/rkN/`: на странице РК1
  видны только страницы РК1. Подпись пункта — текст первого заголовка `# ` страницы, он
  читается из файла при загрузке конфига; в реестре подписи не дублируются;
- **состав сборки** — папка `rk*`, которой нет в реестре, исключается из сборки
  (`srcExclude`). Черновик следующего РК может лежать в `main`, пока его нет в реестре.

### 3.3. Тест реестра

`bun test`, файл рядом с остальными тестами в `scripts/`. Падает, если:

- в папке РК из реестра есть `.md` (не в `diagrams/`), которой нет в `pages`;
- в `pages` есть имя, для которого нет файла;
- `pages` не начинается с `'README'`;
- у страницы нет заголовка `# ` (подписи для меню);
- два РК с одинаковым `dir` или `nav`.

### 3.4. Адреса и главная

- `cleanUrls: true`: `/technopark-guidelines/rk1/csrf`, без `.html`.
- `rewrites`: `README.md` → `index.md`, `rkN/README.md` → `rkN/index.md`. Обзор РК — `/rkN/`,
  главная — корень сайта.
- Главная — корневой `README.md` как обычная страница (`layout: doc`), с таблицей «Рубежные
  контроли». Новый РК — строка в этой таблице руками.
- Ссылки между РК — обычные относительные (`../rk1/basics.md`).

### 3.5. Что не попадает на сайт

`docs/**`, `CLAUDE.md`, `.claude/**`, `scripts/**`, `node_modules/**`, папки `rk*` вне реестра.
Две ссылки корневого README на `CLAUDE.md` и `.claude/skills/eraser-diagrams/SKILL.md`
заменяются на полные ссылки на GitHub (`https://github.com/TP-Prepare/technopark-guidelines/blob/main/…`).

## 4. Отображение содержимого

### 4.1. Ссылки и якоря

- `githubSlug` выносится из `scripts/check-links.ts` в `scripts/slug.ts`; его используют и
  `check-links`, и `markdown.anchor.slugify` в конфиге VitePress. Тесты слага остаются и
  покрывают `й` и `__Host-`.
- Битую ссылку на страницу ловит сборка VitePress (`ignoreDeadLinks` не включается). Якоря
  проверяет `bun run links`.
- Ссылка на `README.md` внутри сайта ведёт на `/rkN/` через `rewrites`. Если VitePress не
  применяет `rewrites` к относительным ссылкам, сборка упадёт на мёртвой ссылке — это первое,
  что проверяется при реализации; обход — правка ссылок в конфиге через `markdown-it`, не в
  текстах.

### 4.2. Mermaid

- Конфиг обёрнут в `withMermaid(defineConfig({…}))` из `vitepress-plugin-mermaid` (точная версия
  2.0.17 в `bun.lock`): плагин превращает блок ` ```mermaid ` в обёртку `div.mermaid`, рисует SVG на
  клиенте и перерисовывает при смене темы.
- Настройки читаемости — `mermaid: { sequence: { wrap: true, useMaxWidth: false } }` в конфиге;
  `.vitepress/theme/custom.css` даёт `.vp-doc .mermaid` горизонтальную прокрутку внутри блока.
- Зависимость `mermaid` (^11) остаётся: это peer плагина и та же основная версия, что внутри
  `@mermaid-js/mermaid-cli` 11.17.0. `bun run mermaid` в CI по-прежнему проверяет, что каждая схема
  собирается.
- Цена: ядро `mermaid` попадает в основной чанк `app.*.js` (около 700 КБ), то есть грузится на каждой
  странице, а не только на страницах со схемами.

### 4.3. PNG eraser-схем

- Обычные картинки Markdown, пути не меняются.
- Увеличение по клику — `medium-zoom` в теме, на изображениях внутри `.vp-doc`; после смены
  страницы привязывается заново.
- В тёмной теме у изображений светлая подложка, отступ и скругление (CSS), чтобы светлый PNG
  не выглядел дырой.

### 4.4. `<details>`

Сырые `<details>` в `questions.md` оформляются CSS так же, как встроенный `::: details`: рамка,
фон, отступы, курсор на `<summary>`. Тексты не меняются.

### 4.5. Русский интерфейс

`lang: 'ru-RU'`, название сайта «Гайдлайны Технопарка», и подписи темы: оглавление «На этой
странице», «Предыдущая страница» / «Следующая страница», «Меню», «Наверх», «Оформление»
(переключатель темы), текст и кнопка страницы 404, все строки окна поиска (кнопка «Поиск»,
«Ничего не найдено по запросу», подсказки клавиш). Оглавление справа — заголовки `##` и `###`.

### 4.6. Поиск

`search.provider: 'local'`. Ищет по всем РК из реестра, с поиском по началу слова (настройки
MiniSearch по умолчанию у VitePress). Морфологии нет — это известное ограничение.

### 4.7. Совместимость текстов

Тексты в первом PR не переписываются. Если Vue не собирает страницу (например, сырой `<` вне
кода), правится точечно этот фрагмент текста, без изменения смысла, и это перечисляется в PR.
Сейчас в текстах нет `{{`.

## 5. Сборка, CI и деплой

### 5.1. Команды

| Команда | Что делает |
|---|---|
| `bun run site:dev` | локальный просмотр с перезагрузкой |
| `bun run site:build` | сборка в `.vitepress/dist` |
| `bun run site:preview` | просмотр собранного сайта |

VitePress запускается под Node (≥ 18 для 1.6.4); Node есть в Docker-образе (образ Playwright).
`.vitepress/dist` и `.vitepress/cache` — в `.gitignore`. Зависимости ставятся из публичного npm
(`bunfig.toml`), проверка «в `bun.lock` нет URL» остаётся.

### 5.2. CI

- В цепочку задачи `build` (внутри Docker-образа) добавляется `bun run site:build` после
  `mermaid:native`.
- На push в `main` задача `build` выкладывает `.vitepress/dist` через
  `actions/upload-pages-artifact`.
- Новая задача `deploy` (`needs: build`, только push в `main`): `actions/deploy-pages`,
  окружение `github-pages`, `permissions: pages: write, id-token: write`,
  `concurrency: { group: pages, cancel-in-progress: false }`.
- Права workflow по умолчанию остаются `contents: read`; права Pages — только у `deploy`.
- Предпросмотра сайта для PR нет (Pages так не умеет): смотреть локально через `site:preview`.

### 5.3. Включение Pages

В настройках репозитория источник Pages — GitHub Actions. Включается до мержа PR, иначе первый
деплой упадёт. Делает автор PR **после подтверждения владельца** (действие внешнее: сайт
становится публичным).

## 6. Документация для авторов

- Корневой `README.md`: раздел «Сайт» — адрес, `site:dev` / `site:preview`, как добавить РК:
  папка `rkN/` → запись в `.vitepress/rk.ts` → строка в таблице «Рубежные контроли».
- `CLAUDE.md`: то же коротко, плюс правило — новая страница РК добавляется в `pages` реестра
  (иначе падает тест).
- Скилл eraser-diagrams не меняется.

## 7. Проверка

Автоматически (CI): `typecheck`, `test` (включая тест реестра и слага), `validate`, `check`,
`fresh`, `links`, `mermaid:native`, `site:build`.

Руками перед мержем — `site:preview` в браузере, снимки экрана в PR:

- главная, верхнее меню, переход в РК1, боковое меню РК1 в порядке реестра;
- поиск по-русски («токен», «SameSite»), переход на найденный раздел;
- якоря `#настойчиво-рекомендуется` и `#cookie-tossing-как-его-останавливают-__host--и-подпись`
  по ссылкам из текста;
- все 6 страниц с Mermaid, в светлой и тёмной теме; 4 PNG и увеличение по клику;
- `<details>` в `questions.md`;
- ширина 375 px: меню, таблицы, код без горизонтального скролла страницы.

После деплоя — короткий проход по живому адресу.

## 8. Не входит

- Перевод текстов на контейнеры и вкладки, `vitepress-plugin-tabs` — второй PR.
- Свой домен, Algolia, комментарии, `llms.txt`, дата правки, журнал изменений, версии по потокам.
- Предпросмотр сайта для PR.
- Переход на VitePress 2.

## 9. Риски

| Риск | Что делаем |
|---|---|
| `rewrites` не применяются к относительным ссылкам на `README.md` | Сборка упадёт на мёртвой ссылке; переписываем ссылку в `markdown-it` в конфиге |
| Vue не собирает какой-то фрагмент текста | Точечная правка текста, перечислить в PR |
| VitePress под Node в Docker-образе ведёт себя иначе, чем локально | Сборка идёт в том же образе, что и CI |
| Mermaid в браузере рисует иначе, чем `mermaid-cli` | Одна основная версия; осмотр всех схем перед мержем |
