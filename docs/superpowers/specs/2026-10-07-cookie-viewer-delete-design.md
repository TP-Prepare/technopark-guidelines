# Удаление cookie в расширении cookie-viewer — дизайн

Дата: 2026-10-07. Статус: на согласовании. Дополняет `2026-10-06-cookie-viewer-design.md`.

## 1. Зачем

Студент отлаживает вход и CSRF и хочет убрать одну cookie, не уходя из вкладки «Все cookie»: мусорную
`refresh_token` от другого приложения на `127.0.0.1` (cookie не разделяются по портам), или
`__Host-csrf` и `access_token`, чтобы проверить повтор после 403 и refresh после 401. Сейчас расширение
только читает, и за удалением приходится идти в Application, где cookie с узким `Path` не видно.

Успех: в таблице у каждой строки есть кнопка удаления, на панели — «Удалить все»; после удаления
студент видит, что на самом деле удалил Chrome, включая cookie, удалённые заодно.

## 2. Как Chrome удаляет (проверено)

`chrome.cookies.remove({ url, name })` принимает адрес и имя, а не конкретную cookie. Проверено
одноразовым расширением в Chrome 156 на `a.probe.test`:

| Вызов | Что удалилось |
|---|---|
| `a`, `http://a.probe.test/api` | все три `a`: `Path=/api`, `Path=/` хоста, `Path=/` домена `.probe.test` |
| `a`, `http://a.probe.test/` | `a` с `Path=/` хоста и домена; `a` с `Path=/api` осталась |
| `s` (`Secure`), `http://a.probe.test/` | ничего, но промис разрешился с деталями, без ошибки |
| `s` (`Secure`), `https://a.probe.test/` | `s` |

Вывод: удаляются все cookie с этим именем, которые ушли бы на адрес; для `Secure` нужен `https`;
результат вызова не говорит, удалилось ли что-то. Поэтому итог определяется только сравнением
списков до и после.

## 3. Решения

| Решение | Почему |
|---|---|
| Крестик в строке и «Удалить все» на панели | решение владельца |
| Оба действия без подтверждения | как Delete и «Clear all» в Application; решение владельца |
| Лишнее не восстанавливать, а сообщить, что Chrome удалил заодно | расширение только читает и удаляет, ничего не записывает; сообщение учит, как `Path` и `Domain` выбирают cookie |
| Итог — сравнение свежих списков до и после, не предсказание | предсказание не учтёт поведение Chrome, которое мы не проверили (схемы, порты) |
| Новых прав нет | `cookies.remove` работает на тех же `cookies` и выданном доступе к сайту |
| Версия `0.2.0` | новая возможность; CI выпустит `cookie-viewer-v0.2.0` после мержа |

## 4. Поведение

### 4.1. Крестик в строке

- Последняя колонка таблицы без заголовка: кнопка `×`, `title` и `aria-label` «Удалить cookie <имя>».
- Нажатие: «до» — `getAll({ url: <адрес строки>, name })`, то есть ровно те cookie, которые Chrome
  удалит (сюда попадает и cookie родительского домена, которой нет в таблице выбранного поддомена;
  проверено в Chrome 156); `remove` с адресом строки; «после» — тот же `getAll({ url, name })`;
  таблица перерисовывается по свежему `getAll({ domain })`.
- Адрес строки: `https`, если `Secure`, иначе `http`; хост — `Domain` без ведущей точки (IPv6 — в
  квадратных скобках, как в `Domain`); путь — `Path`.
- Сообщение над таблицей:
  - удалена только эта строка — сообщения нет;
  - удалена эта строка и ещё другие: «Chrome удалил вместе с ней: `a` (`a.example.ru`, `Path=/`), …. API
    удаляет все cookie с этим именем, которые ушли бы на её адрес.»;
  - строка осталась: «Chrome не удалил `<имя>` (`<Domain>`, `Path=<Path>`).» и текст ошибки API, если
    промис отклонён.
- Чужие изменения между «до» и «после» (страница поставила или удалила cookie) могут попасть в
  «удалены заодно». Окно — два вызова API подряд; принимаем.

### 4.2. «Удалить все»

- Кнопка на панели после «Обновить». Активна, когда на экране таблица и в ней есть строки.
- Нажатие: свежий `getAll({ domain })` (таблица) и `getAll({ url, name })` по каждой её строке,
  `remove` по каждой строке таблицы по очереди (адрес — как в 4.1), те же чтения снова, перерисовка.
- Остались строки таблицы: «Не удалось удалить N из M.» и первая ошибка API, если была (cookie,
  которые страница поставила за это время, не считаются). Всё удалено — экран «У домена `…` нет
  cookie» без сообщения.
- Удаляет строки таблицы — выбранный домен и его поддомены. Одноимённые cookie родительского домена
  Chrome удаляет заодно; они называются сообщением «Chrome удалил также cookie вне выбранного
  домена: …».

### 4.3. Сообщение и автообновление

- Сообщение живёт в состоянии панели отдельно от строк: автообновление (запросы страницы,
  `cookies.onChanged`) его не стирает. Стирают: следующее удаление, смена домена, кнопка «Обновить».
- Начало удаления снимает взведённое автообновление: иначе оно вытеснило бы результат удаления.
- Во время удаления обе кнопки удаления неактивны; повторное нажатие не запускает второе удаление.
- Ошибка самого `getAll` — экран ошибки, как сейчас (`readErrorLine`).

## 5. Код

- `src/cookies.ts` (чистые функции, тесты):
  - `removalUrl(row: CookieRow): string`;
  - `diffRemoved(before: CookieRow[], after: CookieRow[], target: CookieRow): { removed: boolean; alsoRemoved: CookieRow[] }` — по ключу строки (`domain`, `path`, `name`, `partitioned`);
  - тексты: `alsoRemovedLine(rows)`, `notRemovedLine(row, error?)`, `removeAllLine(left, total, error?)`.
  - Ключ строки `rowKey` переезжает из `view.ts` в `cookies.ts` (нужен чистой логике), `view.ts` его
    импортирует.
- `src/view.ts`: колонка с кнопкой (`onRemove`), блок сообщения над таблицей; только
  `createElement`/`textContent`.
- `src/panel.ts`: `removeCookie(row)`, `removeAll()`, поле `notice` в состоянии, кнопка
  `remove-all` в панели; шапка файла «Только чтение» → «Читает и удаляет cookie».
- `panel.html`: кнопка `<button id="remove-all" type="button" disabled>Удалить все</button>`.
- `panel.css`: кнопка в строке без рамки, видна всегда приглушённым цветом (как на макете владельца), цвет ошибки — при наведении и фокусе; цвет сообщения.
- Partitioned-cookie `getAll({ domain })` не возвращает (известное ограничение), поэтому
  `partitionKey` в `remove` не передаётся.

## 6. Тексты и релиз

- «Только чтение» → «Читает и удаляет cookie, ничего не записывает и никуда не отправляет» в
  `manifest.json` (`description`), `tools/cookie-viewer.md` («Что расширение не делает»),
  `scripts/release-extension.ts` (описание релиза) и тест описания.
- `tools/cookie-viewer.md`, «Как пользоваться»: пункт про крестик и «Удалить все» и абзац «Почему
  удалилось больше одной cookie» с примером `refresh_token` на `/` и `/api/v1/auth` (только `example.ru`).
  Скриншот вкладки обновить (колонка с крестиком).
- `version` → `0.2.0`.

## 7. Проверка

- Автоматически: вся цепочка из `CLAUDE.md`; новые тесты:
  - `removalUrl`: host-only, домен с точкой, `Secure`, IP, IPv6, узкий `Path`;
  - `diffRemoved`: удалена только цель; цель и ещё две; цель осталась; пустые списки;
  - тексты сообщений, в том числе `N из M`.
- Руками на собранном `dist` в агентском Chrome, страница — локальный сервер на `127.0.0.1`, cookie
  ставятся одноразовым расширением с `chrome.cookies.set` (как в разделе 2): `a` с `Path=/` и
  `Path=/api` → крестик на `Path=/api` → сообщение о второй `a`; крестик на `Path=/` при живой
  `Path=/api` — удаляется одна; `Secure`-cookie удаляется; «Удалить все» очищает таблицу; сообщение
  переживает автообновление и пропадает по «Обновить». Случай с родительским доменом у IP не
  воспроизвести — он покрыт таблицей раздела 2 и тестами `diffRemoved`. Скриншот в PR и на страницу.

## 8. Не входит

- Редактирование и создание cookie, восстановление удалённых заодно.
- Подтверждение удаления, отмена.
- Удаление partitioned-cookie.
